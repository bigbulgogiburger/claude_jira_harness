# Description 템플릿 (이슈 타입별)

이슈 타입별로 권장 섹션과 작성 예시를 정리한다. 모두 마크다운 (`contentFormat: "markdown"`).

## 공통 규칙

- 후속 grill 문답(harness-workflow ②)·`/jira-plan` 이 디테일을 채우므로 **여기서는 라이트하게**.
- 헤딩은 H2(`##`)부터. H1은 제목과 중복.
- 인수조건은 체크박스 `- [ ]` 형태로 (인터랙티브 체크 가능).
- 모르는 부분은 채우지 않고 비워둔다 (`<TBD>`).

## Story (사용자 가치 기능)

```markdown
## 사용자 가치
<유저로서 X 를 할 수 있다 — 왜 필요한지, 누구에게 가치인지>

## 작업 범위
- <할 일 1>
- <할 일 2>
- <할 일 3>

## 인수조건
- [ ] <검증 가능한 완료 기준 1>
- [ ] <검증 가능한 완료 기준 2>
- [ ] <검증 가능한 완료 기준 3>

## 참고
- 관련 파일: <0-3개>
- 관련 문서/이슈: <있으면>
```

### 예시

```markdown
## 사용자 가치
대시보드 진입 시 핵심 KPI(매출, 활성 사용자, 전환율)를 한눈에 파악할 수 있어,
운영팀이 매일 별도 BI 도구를 열지 않아도 된다.

## 작업 범위
- KPI 위젯 컴포넌트 신규 작성
- 대시보드 라우트에 위젯 배치
- 데이터 조회 API 연결

## 인수조건
- [ ] 대시보드 진입 시 KPI 위젯이 5초 이내 표시된다
- [ ] 데이터 로딩 / 에러 / 빈 상태가 모두 처리된다
- [ ] 모바일 뷰포트에서도 가독성이 유지된다

## 참고
- 관련 파일: src/pages/Dashboard.vue
- 디자인: figma.com/... (있으면)
```

## Task (기술 작업, 외부에 직접 안 보임)

```markdown
## 배경
<왜 이 작업이 필요한지 1-3줄>

## 작업 범위
- <할 일 1>
- <할 일 2>

## 인수조건
- [ ] <검증 가능한 완료 기준>

## 참고
- 관련 파일: <0-3개>
```

### 예시

```markdown
## 배경
KPI 데이터를 매번 원본 테이블에서 집계하면 응답 속도가 2초를 넘는다.
대시보드 위젯에 쓸 수 있는 빠른 집계 엔드포인트가 필요하다.

## 작업 범위
- /api/dashboard/kpi GET 엔드포인트 추가
- 일별 집계 쿼리 작성
- 캐시 정책 결정 (TTL 5분 가정, 확정 필요)

## 인수조건
- [ ] 응답 시간 p95 ≤ 200ms
- [ ] 인증 필요, 권한 없으면 401
```

## Bug (오류 / 기대와 다른 동작)

```markdown
## 환경
- <플랫폼 / 브라우저 / 버전>
- <발견 시점, 빈도>

## 재현 절차
1. <단계 1>
2. <단계 2>
3. <단계 3>

## 기대 동작
<무엇이 일어나야 하는가>

## 실제 동작
<무엇이 일어나는가>

## 영향
- <누가 / 어디에서 / 얼마나 자주>

## 참고
- 스크린샷 / 로그 / 관련 이슈
```

### 예시

```markdown
## 환경
- Safari 17.4 (macOS Sonoma)
- 정산 화면 → 엑셀 다운로드 버튼

## 재현 절차
1. 정산 목록 페이지 진입
2. "엑셀 다운로드" 버튼 클릭
3. 다운로드된 파일 열기

## 기대 동작
파일명이 "정산_2026-05.xlsx" 처럼 한글로 표시된다.

## 실제 동작
파일명이 "%EC%A0%95%EC%82%B0_2026-05.xlsx" 로 URL 인코딩된 채 표시된다.

## 영향
- Safari 사용 운영팀 직원 (전체 운영 인원의 약 30%)
- 매일 발생, 우회 방법 없음 → 매번 수동으로 파일명 변경 중

## 참고
- 같은 패턴 과거 이슈: PROJ-189 (Chrome은 정상)
```

## Epic (큰 이니셔티브)

```markdown
## 목표
<이 에픽이 달성하려는 비즈니스/기술 목표 2-3줄>

## 성공 지표
- <측정 가능한 지표 1>
- <측정 가능한 지표 2>

## 범위
- <포함되는 큰 작업 항목>
- <포함되는 큰 작업 항목>

## 범위 외 (Out of Scope)
- <명시적으로 제외하는 항목 — 스코프 크리프 방지>

## 마일스톤 (선택)
- <Phase 1: 무엇 / 언제>
- <Phase 2: 무엇 / 언제>

## 관련
- 관련 문서: <RFC / 기획안 등>
- 관련 에픽: <있으면>
```

### 예시

```markdown
## 목표
대시보드를 정적 페이지에서 KPI 중심의 액션 가능한 운영 도구로 개편한다.
운영팀이 일일 점검 시간을 30분 → 5분으로 단축하는 것이 목표.

## 성공 지표
- 대시보드 일일 활성 사용자 (DAU) +50%
- 운영팀 일일 점검 시간 ≤ 5분 (주관 평가, 5명 인터뷰)
- 외부 BI 도구 접속 빈도 -70%

## 범위
- KPI 위젯 (매출, 활성 사용자, 전환율)
- 알림/이상 탐지 패널
- 시간 범위 필터 (오늘/주/월)

## 범위 외
- 다국어 지원 (별도 에픽)
- 모바일 전용 레이아웃 최적화 (별도 이슈)
- 권한별 위젯 노출 제어 (V2)

## 마일스톤
- Phase 1: KPI 위젯 + 라우트 (W1-W2)
- Phase 2: 알림 패널 + 필터 (W3-W4)

## 관련
- 기획 문서: docs/dashboard-revamp.md
```

## Sub-task (한 작업의 세부 단계)

```markdown
## 작업 내용
<무엇을 하는지 1-2줄>

## 인수조건
- [ ] <한 줄>

부모: <PARENT-KEY>
```

### 예시

```markdown
## 작업 내용
KPI 위젯 컴포넌트의 골격(레이아웃 + 스타일)을 만든다.
데이터 fetch 는 별도 Sub-task에서 처리.

## 인수조건
- [ ] 위젯이 props로 title / value / delta 를 받는다
- [ ] 디자인 시안과 시각적으로 일치한다 (스토리북 스냅샷 통과)

부모: PROJ-301
```

## 짧은 단일 이슈 (라이트 버전)

벌크 모드나 트리비얼한 단일 이슈에서 더 짧게 쓸 때.

```markdown
## 배경
<1-2줄>

## 작업 범위
- <항목>

## 인수조건
- [ ] <한 줄>
```

### 예시

```markdown
## 배경
환경변수 BASE_URL이 dev/prod에서 다른데 README에 명시가 없어 신규 인원이 매번 헷갈림.

## 작업 범위
- README 의 "환경 변수" 섹션에 BASE_URL 항목 추가

## 인수조건
- [ ] dev / prod 각각의 권장 값과 출처가 명시되어 있다
```

## 작성 시 주의

- **모르는 건 만들어내지 않는다.** "TBD" 또는 빈 줄로 두고 후속 단계에서 채운다.
- **사용자 입력에 없는 디테일을 환각으로 채우지 않는다.** 특히 숫자(목표치, 응답시간), 인명, 일정.
- **인수조건은 패스/페일이 명확해야 한다.** "잘 동작한다" 같은 표현 금지.
- **외래어는 IT 업계 표준 표기**: "리팩터링", "디버깅", "마이그레이션".
